# MVP Requirements

최종 갱신: 2026-10-09 (Asia/Seoul)

상태: Kickoff 및 MVP 세부 요구사항 합의 완료. 2026-10-05 사용자가 세부 요구사항 초안을 그대로 채택했다. 이 문서는 이후 설계·구현·검증의 기준이다.

## 1. Kickoff 결과 — 확정

- 서비스: 아주 간단한 CRUD 게시판.
- 프로젝트 목적: 작은 기능으로 개발·협업·검증·배포·운영·기존 서비스 변경까지 전체 Lifecycle을 경험하고 이후 다른 프로젝트에 적용한다.
- 사용자: 게시판에 접근하는 누구나. 회원과 비회원, 작성자와 다른 사용자를 구분하지 않는다.
- 서비스가 제공하는 기능: 게시글을 작성하고 목록·상세로 조회하며, 기존 게시글을 수정하거나 삭제할 수 있다.
- 핵심 시나리오: 글 작성 → 목록과 상세에서 확인 → 수정 후 내용 확인 → 삭제 후 사라진 결과 확인. 다른 사람이 만든 글에도 같은 기능을 사용할 수 있다.
- 기본 성격: 회원가입과 로그인 없이 사용하는 학습용 웹 게시판.
- MVP 제외 범위: 회원가입, 로그인, 인증/인가, 작성자 구분, 작성자별 수정·삭제 권한. 댓글, 좋아요, 첨부파일, 검색 등 CRUD 외 기능도 첫 MVP에 포함하지 않는다.
- 경험할 개발 주제: 작은 기능 단위의 Issue / Branch / PR / Review, 실제 RDBMS와 Migration, Test / CI, HTTP 및 DB 검증, Container, Backend 배포와 운영, Frontend 개발과 통합, 전체 서비스 배포, 기존 데이터가 있는 서비스의 변경과 재배포.
- Frontend와 배포 후 변경은 전체 Lifecycle에 포함한다. 구체적인 변경 기능은 필요가 생기는 단계에서 정한다.

이 범위는 2026-10-05 사용자의 서비스 선택과 회원·권한 제외 결정을 근거로 한다. 기술 버전, DB 제품, API 경로는 초기 설계에서 확정했다. Frontend 기술과 배포 대상은 DEVELOPMENT_PROCESS의 해당 Lifecycle 단계에서 정한다.

## 2. 확정한 기능과 접근 정책

| 기능 | 사용자 관점의 동작 | 접근 정책 |
|---|---|---|
| 작성 | 새 게시글을 등록한다. | 누구나 가능 |
| 목록 조회 | 등록된 게시글 목록을 확인한다. | 누구나 가능 |
| 상세 조회 | 선택한 게시글의 내용을 확인한다. | 누구나 가능 |
| 수정 | 기존 게시글의 내용을 바꾼다. | 작성자 구분 없이 누구나 가능 |
| 삭제 | 기존 게시글을 삭제한다. | 작성자 구분 없이 누구나 가능 |

사용자 계정, 작성자 식별자, 글 비밀번호로 수정·삭제를 제한하는 기능은 만들지 않는다.

## 3. 세부 요구사항 — 확정

아래 정상·실패 동작과 데이터 보존 규칙을 구현하고 검증한다.

| 항목 | 요구사항 | 확인할 이유 |
|---|---|---|
| 게시글 입력 | 제목과 본문을 입력한다. 둘 다 일반 텍스트이며 본문은 줄바꿈을 허용한다. | 작성·수정 화면과 입력 검증의 기준 |
| 필수 값 / 길이 | 제목 1~100자, 본문 1~5,000자. 누락, 빈 문자열, 공백만 있는 값은 거절한다. | 잘못된 입력과 경계값을 테스트할 기준 |
| 표시 정보 | 게시글 식별자, 제목, 본문, 작성 시각, 수정 시각을 제공한다. 목록에는 본문을 제외한다. | 글 선택과 수정 결과 확인에 필요한 정보 |
| 목록 | 첫 MVP에서는 전체 목록을 최신 작성 순으로 보여준다. 글이 없으면 빈 목록을 보여준다. 수정해도 작성 순서는 바꾸지 않는다. | 첫 화면의 동작을 단순하게 정한다. 페이지 나누기는 필요가 생길 때 별도 변경으로 다룬다. |
| 수정 | 제목과 본문을 함께 수정한다. 작성 시각은 유지하고 수정 시각을 갱신한다. | 수정 전후에 보존해야 할 정보 |
| 삭제 | DB에서 실제로 삭제한다. 휴지통과 복구 기능은 포함하지 않는다. | 삭제 후 조회 결과와 데이터 보존 범위를 정한다. |
| 없는 게시글 | 존재하지 않거나 삭제된 글의 상세 조회·수정·삭제는 찾을 수 없다는 실패 결과를 반환한다. | 실패 동작을 일관되게 검증한다. |
| 잘못된 입력 | 작성·수정을 거절하고 잘못된 항목을 알린다. 기존 글은 그대로 유지한다. | 요청 실패로 데이터가 잘못 바뀌지 않게 한다. |
| 데이터 보존 | 저장된 게시글은 애플리케이션 재시작 후에도 남는다. Schema 변경을 위해 기존 DB를 삭제하지 않는다. | 실제 저장과 이후 서비스 변경을 검증한다. |

## 4. 검증 시나리오

Backend 프로젝트와 생성 기본 테스트는 준비됐지만 게시글 기능과 아래 시나리오의 테스트는 아직 구현하지 않았다. 아래는 이후 구현 완료를 판단할 관찰 가능한 결과이며, 현재 검증을 통과했다는 의미가 아니다. 실제 진행 상태와 실행 검증 결과는 [PROJECT_STATE.md](PROJECT_STATE.md)를 따른다.

1. 정상 제목과 본문으로 작성하면 새 글을 식별할 수 있고, 목록·상세에서 저장한 내용을 확인한다.
2. 글이 없으면 목록 조회가 성공하고 빈 목록을 반환한다.
3. 여러 글을 작성하면 최신 작성 순으로 표시한다.
4. 정상 입력으로 수정하면 상세 조회에서 바뀐 내용과 수정 시각을 확인하고 작성 시각은 유지된다.
5. 제목 / 본문의 누락·공백만 있는 값·길이 초과를 거절한다. 최대 길이의 정상 입력은 허용한다.
6. 실패한 수정 후 다시 조회하면 기존 내용이 유지된다.
7. 삭제하면 목록에서 사라지고, 해당 글의 상세 조회·수정·삭제는 찾을 수 없다는 결과를 반환한다.
8. 별도의 사용자 인증 없이 위 기능을 수행할 수 있다.
9. 글을 저장하고 애플리케이션을 재시작한 뒤에도 조회할 수 있다.
